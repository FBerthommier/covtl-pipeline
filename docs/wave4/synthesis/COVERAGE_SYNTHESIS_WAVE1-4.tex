\section{Executive Summary}
\label{sec:summary}

This report consolidates the results of four successive coverage and
test-hardening campaigns (``waves'') conducted on
\pkg{vtl-synth}~1.1.3, the articulatory-synthesis layer of the
\pkg{covtl-pipeline} repository (HEAD
\code{3903645d3f91862c49f934aee94e2b2cc09c4bd}, November 2026). It is
intended for the package documentation that accompanies a PyPI
promotion: it documents the methodology, the measured evidence, and the
reasons why the package can be promoted with a defensible quality
position.

Across the four waves, combined branch coverage of the constant scope
(the \pkg{vtl\_synth} package, excluding the companion sandhi rule
package) rose from \pct{73.8} to \pct{76.6}, while the test suite grew
from 474 tests (with 2 failures at the first audit) to 504 collected
tests, of which 501 pass and 3 skip by design. More importantly than
the raw percentage, the campaign produced three layers of behavioral
guarantees that a coverage number alone cannot express: byte-level
regression pins on the synthesis output (49 SHA-256 baselines over
tract and glottis matrices), platform-independent quantized pins on
pause trajectories, and structural invariants (block schedules, exact
plateau values) that survive cross-platform floating-point noise. It
also surfaced and fixed five real defects---two API-breaking bugs, one
silently inoperative feature (phonation-mode tag overrides), one
misleading warning path (consonants reported as ignored characters),
and one dead-on-arrival computation channel (the branch-B effort
envelope, unconditionally overwritten by the engine's own effort).

The final state of the measured scope decomposes honestly: the
remaining uncovered lines are concentrated in the deprecated V1 engine
(\code{continuous.py}, \code{trajectory.py}, \code{prosody\_source.py},
\code{parsing.py}), the deliberately
lightly-tested video encoding layer, and the grapheme-to-phoneme tables
of languages other than French. Excluding those three
deliberate omissions, the ``honest ceiling'' of the package is
\pct{78.6}, which we consider a sound basis for a PyPI release: every
line of the actively maintained signal path is either covered by the
test suite or explicitly documented as out of scope, and the synthesis
outputs are pinned bit-for-bit against regression.

A companion document, \emph{Wave-4 Commit Log: Rationale and
Non-Regression Evidence} (\code{COMMIT\_LOG\_WAVE4.pdf}, in the
\code{docs/wave4/} directory of the repository), records the eight
atomic commits that carried the final wave: the logical justification
of each change and the test series that proves non-regression.

\section{The Measured Artifact}
\label{sec:artifact}

\pkg{vtl-synth} is a Python~3.12 package that converts phonetic input
(SAMPA-style keys, syllable separators, pause markers) into
articulatory parameter trajectories for the VocalTractLab (VTL~2.4.2)
synthesizer, in the Maeda polar-coordinate tradition. The measured
scope of this campaign is:

\begin{itemize}[leftmargin=1.4em, itemsep=0.15em]
  \item \textbf{Core signal path} (engine ``syl''):
        \code{core/syltraj.py} (syllable-level trajectory
        builder), \code{core/build\_phrase\_tract.py} (phrase
        orchestrator), \code{core/enveloppe.py} (gesture
        anchors, feature timers, timed envelope),
        \code{core/assemble\_tract.py},
        \code{core/glottal\_source.py}, and the effort,
        notation, and support modules
        (\code{core/amplitude\_envelope.py},
        \code{core/notation.py}).
  \item \textbf{Deprecated V1 engine} (kept as a legacy reference,
        guarded by a \code{DeprecationWarning}):
        \code{core/continuous.py}, \code{core/trajectory.py},
        \code{core/prosody\_source.py}, \code{core/parsing.py}.
  \item \textbf{Utility layers}: speaker registry and per-speaker
        constants, French g2p, chunking, prosody $f_0$.
  \item \textbf{Companion package} (excluded from the headline number):
        \code{utils/sandhi/} ships as a Branch-A hook stub; the full
        rule set (Branch B) lives in the separate
        \pkg{covtl-sandhi} package and is tested in its own
        repository.
\end{itemize}

All measurements in this report were taken with pytest~9.0.2,
pytest-cov~7.0.0, Coverage.py~7.13.1 (branch coverage enabled),
numpy~2.1.3, and the \pkg{vocaltractlab-cython} 0.0.17 engine
wheel (speaker JD3 active), on Linux. The repository CI exercises
the same stack on Windows runners, which is where the regression
baselines were generated and acoustically validated.

\section{Campaign Methodology}
\label{sec:methodology}

The four waves were not four independent test-writing efforts. They
formed a single escalating protocol in which each wave's \emph{output}
became the next wave's \emph{instrument}. This section documents the
methodological tools in the order they were introduced, because their
composition is what makes the final evidence strong.

\subsection{Wave 1 --- Baseline Measurement (Read-Only Audit)}
\label{sec:wave1}

The first wave measured the repository exactly as received: no source
modification, no test addition. It established the initial state
(\pct{73.8} combined, 474 tests collected, 2 failing) and, more
importantly, produced the first version of the \emph{coverage
decomposition}: per-module tables separating ``structurally unreachable
via the public API'' from ``reachable but untested.'' The audit
introduced two conventions that every later wave inherited:

\begin{itemize}[leftmargin=1.4em, itemsep=0.15em]
  \item \textbf{Constant scope}. The headline number always excludes
        the sandhi companion package, so that waves remain comparable
        even when the Branch-B rules are installed for a measurement.
  \item \textbf{Dead-code ledger} (\code{LEGACY.md}). Every exclusion
        from the denominator is written down with its evidence (grep
        importers, design notes), so ``coverage'' never silently
        becomes ``coverage of the easy parts.''
\end{itemize}

\subsection{Wave 2 --- Phonetic-Input Corpus}
\label{sec:wave2}

The second wave targeted the model's own input notation, which the
first audit had identified as the largest coherent untested surface:
syllable categories (CV, CCV, VCV), separators (space, \code{|},
\code{\%}, \code{.}), and the cluster semantics controlled by the
companion \pkg{covtl-lambda} analyzer (C.C dotted forms disable the
nasal cluster of the pointed pair; plain CC forms keep it). The
resulting corpus, \code{tests/test\_phonetic\_model\_inputs.py}, is
parametrized over 97 test cases and runs in under six seconds, which
made it the natural payload of the fast CI lane introduced in wave~3.
Wave 2 also introduced the \code{sys.settrace} sweep over 25 pause
forms that later justified the dead-code removal of wave~4: the tracer
recorded, for every statement of the pause-handling region of
\code{build\_global\_pval}, whether any real input could ever reach it.

\subsection{Wave 3 --- Targeted Lines, Hardened Pins, CI Lanes}
\label{sec:wave3}

The third wave attacked the specific missing lines enumerated by the
wave-2 measurement. Its methodological contributions were:

\begin{enumerate}[leftmargin=1.6em, itemsep=0.2em]
  \item \textbf{Targeted tests with line citations}. Each new test
        documents, in its docstring, the exact line it activates and
        why that line is reachable (26 tests in
        \code{tests/test\_wave3\_targeted.py}).
  \item \textbf{Platform-independent regression pins}. The existing
        byte-level SHA-256 pins had been generated on Windows; on
        Linux the last bits of the \code{exp}/\code{arccos} chains
        differ. The fix was not to relax the check but to
        \emph{quantize before hashing} (round to $10^{-9}$), plus
        structural invariants (block schedule; each vowel plateau
        equals the algebraic projection \code{compute\_P(*target)}
        exactly; inter-step continuity bound). The quantized pin is
        machine-independent; a real trajectory change still trips it.
  \item \textbf{Batch-load test} with label-sanitation uniqueness,
        locking the silent-dict-overwrite failure mode of
        \code{build\_batch\_tract}.
  \item \textbf{CI lanes}: a \code{phonetic-fast} job (the wave-2
        corpus, $\approx$6\,s) ahead of the full suite, and the
        \code{pyproject.toml} coverage configuration that makes the
        local and CI measurements identical.
  \item \textbf{Documentation of open defects}: two API bugs
        found during the campaign---\code{parse\_to\_anchors}
        raising a \code{TypeError} on a renamed keyword, and
        \code{ALL\_K} missing the voiceless consonants---were
        documented as
        findings with proposed fixes, but deliberately \emph{not}
        applied---the measurement wave stayed read-only with
        respect to source behavior, which is what made its
        coverage numbers interpretable.
\end{enumerate}

\subsection{Wave 4 --- Applied Recommendations on a Fresh Clone}
\label{sec:wave4}

The final wave applied the wave-3 recommendation set as eight atomic
commits on a freshly cloned repository, with the proof obligations
reversed: this time the burden was on \emph{non-regression}. Its
instruments were:

\begin{itemize}[leftmargin=1.4em, itemsep=0.15em]
  \item \textbf{Bit-identity harness} (\code{bitident.py}): 22 pause
        phrases hashed before and after each refactoring commit, at
        three granularities---raw SHA-256, quantized ($10^{-9}$)
        SHA-256, and block structure. This harness earned its keep
        immediately: the first attempted edit of the dead-arm removal
        inverted the live/dead branches, and the hash comparison
        flagged 88 structural differences \emph{before any commit was
        made}. The corrected version is byte-identical on all 22
        phrases.
  \item \textbf{Regression baselines}: the 49 pinned
        tract/glottis SHA-256 baselines (schema 3, quantized to
        $10^{-6}$, speaker JD3) pass unchanged after every commit.
  \item \textbf{Functional deltas} for behavior changes that are the
        \emph{point} of a fix: phonation-mode overrides now
        measurably alter the glottis vector (max abs difference
        1.04 / 1.39 / 1.65 for breathy / creaky / whisper against
        the modal baseline, versus $\approx$0.13 before the fix).
  \item \textbf{Patch-level validation}: the whole wave ships as a
        \code{git format-patch} series whose application on a virgin
        clone of the base commit reproduces a byte-identical tree and
        a green suite.
\end{itemize}

\subsection{Cross-Cutting Rules}
\label{sec:rules}

Three rules were applied throughout and are recommended for reuse:

\begin{enumerate}[leftmargin=1.6em, itemsep=0.2em]
  \item \textbf{Never change behavior and measure coverage in the same
        step.} Waves 1--3 measured; wave 4 changed. Each wave's numbers
        are interpretable because the other variable was held fixed.
  \item \textbf{A coverage number is a thermometer, not a proof.}
        Every claim of non-regression in this campaign rests on hashes
        and invariants, never on ``coverage went up.''
  \item \textbf{Exclusions carry their evidence.} The dead-code ledger
        (\code{LEGACY.md}) and the honest-ceiling decomposition
        (Section~\ref{sec:ceiling}) mean the reported percentage can
        always be audited down to individual files.
\end{enumerate}

\section{Non-Regression Evidence}
\label{sec:nonregression}

The PyPI promotion case rests on the following concrete, reproducible
evidence rather than on the coverage percentage.

\subsection{Layer 1 --- Byte-Level Output Pins}
The baseline suite \code{test\_regression\_baselines.py} pins the
tract and glottis matrices of 8 canonical phrases (parametrized over 49 test cases with
per-speaker variants) by SHA-256 of the quantized matrices (schema~3,
$10^{-6}$, speaker JD3, engine \code{syl}). These pins passed
unchanged after every wave-4 commit---including the dead-arm removal,
which is the strongest available statement that the refactor was
behavior-preserving.

\subsection{Layer 2 --- Platform-Independent Trajectory Pins}
\code{tests/test\_syltraj\_double\_pause.py} guards the double-pause
fix region: single-pause sequences must remain behaviorally identical
to the pre-fix engine. The check combines a quantized SHA-256 pin
($10^{-9}$), which removes cross-platform \code{libm} last-bit noise
while still catching any real trajectory change, with structural
invariants: exact block schedule, vowel plateaus equal to the
algebraic target projection \emph{exactly} (no floating-point slack),
and a bounded inter-step jump.

\subsection{Layer 3 --- Bit-Identity Harness for Refactors}
\code{bitident.py} (shipped with the patch series) hashes 22 pause
phrases---raw, quantized, and block-structure---and compares before
and after any candidate refactor. It detected the one editing error
made during wave 4 before that error reached version control.

\subsection{Layer 4 --- Functional Assertions for Intended Changes}
Where a commit's purpose is a behavior change (the consonant fix, the
phonation-mode fix), non-regression is asserted functionally: the
previously wrong observable is now correct (no false ``ignored''
report; exact phonation event sets; anchor chains), and every
unrelated observable is pinned by layers 1--3.

\subsection{Layer 5 --- Patch Application Validation}
The entire wave-4 series was applied with \code{git am --keep-cr} to
a virgin clone of the base commit; the resulting tree is
byte-identical to the developed branch (\code{git diff} equality) and
its suite is green. The \code{--keep-cr} requirement is documented in
the patch README: the engine sources are CRLF blobs, and applying
without the flag fails on \code{syltraj.py}---a symptom worth knowing
rather than a defect.

\section{The Case for PyPI Promotion}
\label{sec:pypi}

\subsection{What a Downloader Is Buying}

A user who installs \pkg{vtl-synth} from PyPI obtains a package
whose actively maintained signal path is at \pct{78.6} combined
coverage with the remainder explicitly ledgered; whose synthesis
outputs are pinned by 49 SHA-256 baselines so that any regression in
the articulatory pipeline is caught before release; whose phonetic
input notation (the user-facing surface) is locked by a 97-case corpus
that runs in six seconds; and whose CI runs four lanes---a fast
phonetic gate, the full suite, a five-speaker baseline matrix, and a
sandhi composition lane---on every push and pull request.

\subsection{Known Limitations, Stated Plainly}

Three limitations belong in an honest promotion document. First, the
coverage percentage of the whole repository (\pct{64} combined
including the sandhi stub and every excluded layer) is lower than the
headline; the decomposition of Section~\ref{sec:ceiling} is the
number a reviewer should quote. Second, the regression baselines are
pinned to speaker JD3 and to the engine version; the test file
explicitly skips when another speaker is active, so a speaker swap
must regenerate the baselines deliberately. Third, the
